# Cluster v0.546.0 | TD6 G26 Grouped Batch B — Package / Inventory Delivery Authority

**Source implementation complete for the scoped authorization work. G26 remains OPEN.** Parent: `Cluster-v0.546.0-TD6-G26-BatchA-Packet-Compliance-Operations-Source.zip`. This grouped batch connects Package grants, Inventory custody and Desktop device/release policy rather than shipping independent tiny workstreams. It does not certify OS software installation, native helper builds or release rollout.

## Connected implementation

1. **Optional binding to a canonical Inventory asset.** A new `ManagedPackageSeatRequirement` is keyed by canonical Package ID and references an existing digital/license `StudioInventoryAsset` (new additive PostgreSQL migration). There is no copied license key, Vault secret, stored token, or second allocation ledger. Packages without the binding preserve existing independent reviewed Package entitlement behavior.
2. **Runtime distribution enforcement.** `packageSeatEligibleIds` checks current per-user `StudioInventoryAllocation` status, positive quantity, expiry and current asset kind/status. The canonical `readDevicePackageTargets` now filters by this separate seat authority before signature trust, rollout/pins and prerequisite resolution. Existing device-bound routes reuse that resolver for new downloads, resume/recovery authorization, positive receipts and deployment grants. A revoked/expired/retired seat cannot be bypassed by a device pin or signed release. The user still requires a separately reviewed, unexpired Package entitlement.
3. **Impact-preview → deliberate commit.** Admins search the existing Inventory catalogue, choose a valid asset, review how many unexpired Package grants currently have matching seat custody, provide a reason and type `REQUIRE INVENTORY SEAT`. A preview SHA-256 fingerprint covers active grant IDs/revisions/expiry, relevant allocation IDs/revisions/expiry and asset revision/state. Binding commits in a Serializable transaction, locks owning Package + Inventory asset rows and compares the fingerprint before insertion. The audit event is created within the same transaction. The binding is additive-only in this route: cannot be removed or retargeted without a future separate reviewed governance workflow. Do not interpret the affected-grants count as a count of active signed-in people; accounts and device eligibility remain independent constraints.
4. **Effective recipient readiness inspection.** A new admin-only, on-demand POST inspection explains one recipient/device/package request across account state, Package entitlement, optional Inventory seat, verified Desktop registration, signed rollout or pin, and complete prerequisite chain. Results deliberately omit license/Vault secrets, artifact bytes, device-proof credentials, deployment grants and full signed public-key contents. `canRequestDistribution` is not OS installation authorization or evidence of installation. No background polling was added.
5. **Source-scope and UX reliability.** Package entitlement loading now explicitly fails on more than 500 grants rather than silently truncating at 100. The seat resolver and impact preview use bounded DB reads with explicit scope errors; impacts reject incomplete enumeration. Stale UI requests are ignored after selected assets/recipients change. Inherited historical mock fixtures were extended with a no-seat-binding stub to preserve their original unbound Package behavior; the new focused tests execute the actual seat policy.

## Boundaries and deferred evidence

- **New database migration must be executed** against PostgreSQL before server routes can use the new Prisma delegate. Prisma generation, SQL migration and live Serializable concurrent commits **not run here**; Node available in this environment is v22.16.0, while Cluster pins Node 24. The lean archive lacks installed workspace dependencies and generated Prisma client.
- **No automated installer, native binary modifications, secret propagation or physical deletion.** Existing Go stager source passes its local tests, but no Windows/Qt/native process or MSI execution acceptance was performed. Vault stays the owner of secret material and Inventory stays the owner of individual allocations.
- An already minted offline-valid signed deployment grant lasts up to its existing short TTL (60 seconds); new server authorization decisions re-check the seat, but cannot retroactively revoke an offline token without native online revocation protocol. Document and test that boundary in native release certification.
- A seated user can still become ineligible after an admin inspects readiness; inspection is a point-in-time observation and never a durable reservation. Live recipient proof, package/seat revocation races, performance plans, and multiuser browser acceptance remain pending.
- Coverage beyond 500 simultaneous Package grants and >500 unexpired grant impact inspections deliberately fails closed pending paged, snapshot-safe scaling.
