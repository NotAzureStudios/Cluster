# G26 Pass 37: Separately authorized supervised per-user MSI repair

**Cluster v0.546.0, G26 Pass 37, 2026-10-24.** Builds directly on the read-only Pass 36 lifecycle review. This is an implementation checkpoint, **not a Windows runtime certification**.

## Implemented in executable source

- Server opt-in `CLUSTER_ALLOW_SUPERVISED_MSI_REPAIR=true` is a **separate**, default-disabled administrative setting. Only authorized administrators on an authenticated, unrevoked device with the exact current signed per-user Windows MSI release can mint a short-lived one-use `repair` grant. The grant is Ed25519 signed by the independently provisioned *control* key, binds the release identity **and exact SHA-256 of the existing installation receipt**, and cannot authorize fresh install, managed content deployment or a different MSI release.
- Native Go `repairSupervisedMSI` re-verifies publisher identity, signed kit, staged MSI digest, ProductCode/Version and signed prerequisite evidence. It acquires the profile-wide admission lock and per-Package lock; refuses any earlier lifecycle action; requires the exact prior installation receipt to represent a completed, matching, registered user MSI with coherent before/after registration; blocks known dependents, unresolved prerequisite custody, machine-wide/mixed-scope installations and registration drift. It rechecks these after consuming the one-use grant. The Windows executor uses fixed `msiexec /fomus`, the signed MSI source protected by the held immutable file handle, a suspended child assigned to the OS Job Object, bounded execution, and a pre-resume registration and dependency recheck.
- Before grant consumption, the helper writes an exclusively created `msi-lifecycle/<packageKey>.json` durable receipt. The record transitions from `repair_prepared_not_launched` to `repair_started_outcome_unknown` before launching, then to a process-exit outcome. Failed writes and interruptions leave evidence requiring manual review; any prior journal **prevents replay**. The original installation receipt remains untouched; the process exit is **never** an installed-application-health attestation.
- Qt adds `package.msiRepairStatus` read-only evidence and `package.repairMsi` guarded action with independently pinned publisher/control keys, native typed `REPAIR <packageKey>` confirmation, fixed helper action, distinct outcome states and no arbitrary 30-second process kill. Desktop offers journal inspection and repair only for matching read-only lifecycle candidates with no known blockers; both verify the evidence independently and request a fresh grant *after* native preflight.
- Fixed a pre-existing Desktop authorization race: an obsolete async action could hold the one-at-a-time grant flag forever after target refresh. The separate grant-owner generation token now releases its own lock while preventing an older operation from resetting a newer action.

## Verification and intentional limits

- Executed production TSX repair validators and grant-preflight handlers against forged receipts, altered ProductCodes, stale targets, wrong signed grant purpose and generation races. Native Go tests exercise Ed25519 grant separation, mandatory prior SHA, journal O_EXCL/anti-replay, corrupt/symlinked receipts, current-user-scope classification, registration failures. The inherited Pass14-36 scripts and source scan pass. Go unit/race/vet and Windows x64 helper/test cross-compilation pass. Exact counts are in the integrity report.
- **Not implemented or claimed:** a self-healing retry, automatic journal deletion, user/machine scope migration, OS process-health attestation, a dependency-complete OS scan, MSI upgrade/uninstall, dependency-aware rollback, linked Qt binary and live Windows/PostgreSQL certification. Windows Installer service can spawn work outside the child Job Object. The opt-in repair should remain disabled in actual deployments until Windows runtime validation and operator signoff.
- G26-10, G26-11, CERT-12 remain open. Continue implementation (uninstall/upgrade/rollback), without letting missing certification prevent source development.
