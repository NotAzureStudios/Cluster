# Cluster v0.546.0 | G26 Pass 7: Native Streaming-State Diagnosis

**Exact parent:** `Cluster-v0.546.0-G26-Native-Transfer-Qt-Boundary-Pass6-Source.zip`. Builds on Pass 5 streaming state and Pass 6 Qt response redaction. This is an on-demand, read-only forensic improvement, **not** automatic repair or permission to install.

After introducing checkpoint schema 2, an incomplete or incompatible Go SHA-256 streaming-state record could be fully verifiable by explicit recovery but was previously reported as an undifferentiated `checkpoint_invalid`. The native `transfer-diagnose` helper now performs a second **strict core-metadata-only read** if full metadata/hash-state validation fails. If the schema, transfer identity, bounds, prefix digest, tail digest, timestamp, state and nonsecret offer are structurally valid, diagnosis emits `streaming_hash_state_invalid_full_recovery_required`, marks manual review mandatory, and returns the published/expected byte counters. If core metadata is invalid or belongs to another transfer, it retains `checkpoint_invalid`.

**No disk payload hash is performed during this classification and no checkpoint/lock/payload bytes are modified.** Consequently, the classification is not evidence that recovery will succeed. Qt continues to require authenticated origin and on-demand action; Desktop already displays the diagnostic state and the notice that recovery requires explicit review. The operator-confirmed `transfer-recover` operation independently validates the entire last-published prefix before reconstructing the hash state; corrupted data still fails.

Executable native tests cover corrupted streaming-state metadata, unchanged disk contents during diagnosis, and refusal to reconstruct if actual saved-prefix bytes are corrupted. New `cluster-g26-streaming-diagnostic-contract-tests.mjs` confirms authority separation and the user-facing read-only warning. The single master register keeps G26-08/09 open pending broader Transfer Center and live Windows 10/Qt certification.
