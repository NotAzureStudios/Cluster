# Cluster v0.546.0 | TD6 G26 Workstream 5: Provider Finalization, Cleanup Fencing & Retention Accounting

**Parent:** G26 WS4 (`Cluster-v0.546.0-TD6-G26-Workstream4-Upload-Commit-Recovery-Source.zip`). **G26 OPEN, G25 source-closed.** This checkpoint is not production certification.

## Connected source implementation

1. **Direct multipart part authority:** authorization is recorded in a short Prisma transaction using a PostgreSQL `FOR UPDATE` lock on the owning `UploadSession` row. Part acknowledgments hold the same DB row lock, re-read the live session, require prior authorization, refuse a different ETag for an already-acknowledged part, and update the aggregate/parent progress inside that same transaction. The external provider URL is requested only after the authorization transaction commits. Presigned URLs can remain valid for their short TTL even after an application pause; the server will not accept a stale acknowledgment.
2. **Provider completion fencing:** `OPEN` must be claimed via conditional DB update to `FINALIZING` before any remote completion call; competing completion, pause, acknowledgement, abort, and expiry cleanup cannot claim this session. Reload and validate the *complete contiguous part list* after claiming. Missing parts reset safely to OPEN before provider work. Once the remote call begins, an ambiguous provider outcome remains `FINALIZING` for governed reconciliation, not repeated external completion. Verified correct size and SHA-256 lead to a `FINALIZING`-qualified `COMPLETED` update. Provider size/checksum mismatches retain remote evidence and enter `REVIEW_REQUIRED`, with a governed journal entry.
3. **Disposition and expiration:** cancel and expiry require DB state claims (`ABORTING` and `CLEANING`) before any provider abort, evidence journal or row removal. Database deletion precedes local file removal; direct provider object deletion is never done. A failed provider abort or journal leaves the claimed record for operator reconciliation. Cleanup skips `FINALIZING`, `ABORTING`, `CLEANING`, and `REVIEW_REQUIRED`; repeated expiry scans do not retry an ambiguous operation. Expiry checks re-read current status/expiration and use conditional claims, with existing local filesystem mutex preserved for Cluster-proxied staging.
4. **Durable Library job ownership:** a completed upload referenced by an active `library.transfer.finalize` background job is protected from manual cancellation as well as expiry cleanup. Only completed sessions can be consumed. Client idempotency keys no longer implicitly replace paused or quarantined sessions and discard their audit trail.
5. **Capacity and operations:** unresolved recovery/disposition states remain in byte and session quotas *even after TTL*, preventing indefinite remote-byte leakage outside quota calculations. Admin upload-pressure diagnostics now include `recoveryRequiredSessions` as a separate count. A paused/completion-uncertain browser transfer gets specific preserved-evidence/reconciliation feedback, not ordinary “resume” guidance.
6. **Library bulk retention verification:** the inherited 16-case transactional background bulk suite passed: immutable selection, access rechecks, legal/Records/lock/child protections, chunk atomicity and audit evidence. This workstream does **not** claim a new Library bulk feature or modify its existing legal-hold semantics.

## Boundaries, safety and follow-up

- **No live PostgreSQL, Prisma client generation, Node24 compilation, real S3 provider race test, two-server concurrency, authenticated browser, Windows or Qt certification.** Controlled mocks test the intended transitions, not the database/provider's deployment semantics. No new Prisma migration is required: session status is already a string.
- `FINALIZING`, `REVIEW_REQUIRED`, `ABORTING`, `CLEANING` are **operator-reconciliation states**. Reconcile provider multipart ID, remote object identity/version, SHA-256, durable upload row and Library job references before any manual disposition. Do not automatically reset these states, delete remote objects, reuse an idempotency key, or infer remote rollback from a lost HTTP response.
- Presigned URLs are not instant-revocable. Object storage policy must enforce restricted key namespaces, short TTL, multipart limits and actual content integrity. Existing deferred-object journal records ownership but does not authorize deletion. A distributed worker lease and automated idempotent reconciliation tooling remain future G26 work.
- **Next G26:** job-scoped upload/provider reconciliation UI with audited operator actions; Library retention and bulk impact review beyond inherited protections; explicit Packet delivery assignments/required acknowledgments; Packages, Inventory/Vault, native installation/update rollback. Keep source completion separate from deployment certification.
