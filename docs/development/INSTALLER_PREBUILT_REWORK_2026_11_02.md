# Installer Overhaul | Cluster 1.0

**Scope:** prebuilt Windows Server installation with no on-target compilation. `main` is unchanged until a reviewed PR is merged.

## Completed source changes

- The installer packager defaults to `prebuilt`, requires Windows x64, a matching npm lockfile, a clean traceable Git commit, built native PE/Server/Web/Prisma outputs and compiled web JavaScript assets.
- The internal runtime archive includes an allowlisted SHA-256 file manifest and generated `config/prebuilt-runtime.json` bound to the release identity and source commit. Workspace junctions are omitted from ZIP extraction and recreated locally.
- The Go EXE validates the embedded prebuilt metadata and refuses source-only archives/dragged untrusted ZIPs in normal mode.
- PowerShell checks archive and build-product hashes, provisions the private verified Node runtime only, runs preflight/smoke checks, and continues using the managed installation's existing preservation, rollback and root-launcher safety behaviors.
- The source compilation path remains only with explicit `CLUSTER_INSTALLER_DEV_SOURCE_BUILD=1` and `CLUSTER_INSTALLER_PAYLOAD=source` for development.
- The Server release-profile build now performs fresh npm installation, native tests/builds, Prisma generation and Server/Web compilation on the build runner **before** packaging.
- Added Go identity tests, source-contract checks and an independent Windows workflow.

## Unverified / blocking

1. The tracked root `package-lock.json` is still missing. The production prebuilt installer must fail, not invent a dependency graph.
2. Full Windows-native artifacts are unavailable in the current environment. No production installer EXE was generated by this pass.
3. The embedded runtime's real size is not measured. The current ZIP builder has an uncompressed 2 GiB safety budget; if exceeded, use a verified/signed external payload rather than loosening safety limits.
4. Windows 11 fresh install, repair, upgrade from a managed older build, rollback with simulated failures, user data preservation, service startup, PostgreSQL 18.6 restore and Library permissions are not yet certified.
5. Release authenticity is provided only when the existing Ed25519-signed Server release publisher verifies the **exact installer** against the source-matched build receipt. The internal archive manifest is integrity evidence, not a signature.
6. Desktop Qt 6.x distribution remains independent and requires its own parity/version checks.

## Acceptance rule

**Do not merge into `main`, publish binaries, bump the release identity or claim 1.0 stable** merely because the source/Go contract tests pass. Merge to `development` after the Windows CI contracts are green, then address the missing lockfile and execute real installation acceptance on a Windows machine.
