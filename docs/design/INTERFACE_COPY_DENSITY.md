# Cluster Interface Copy Density Standard (RC24)

Keep primary workflows terse. Show the action, the field, and the result; do not surround each control with instructions about what the label already says.

- Dialogs: one short action title, essential field labels, immediate error, and one primary action. No duplicate eyebrow, step counter, paragraph, or character counter unless it solves a real ambiguity.
- Sensitive changes: preserve confirmation and access information when it materially affects user decisions. Never remove privacy warnings, failure recovery directions, authorization explanations, or audit evidence for decoration's sake.
- Onboarding: required actions first. Put advanced network, security and compliance explanations under an expandable details section or contextual help, not repeated on each step.
- Workspaces: surface content before dashboards, avoid redundant navigational headers; keep status and details available on demand.
- Error messages: state what failed and what the user can do. Don't report a download completed merely because a link was clicked; don't claim server connectivity without a network response.
- Reusable controls: one shared PIN entry (numeric keyboard and on-screen pad) for both authenticated PIN prompts and sign-out kiosk PIN verification. Different server authorization routes must remain separate.

Validation: inspect modal layouts at 100/125/150% scaling and both light/dark themes; ensure field labels survive accessibility, tab order and screen readers. This policy is applied incrementally rather than indiscriminately deleting every explanation in the app.
